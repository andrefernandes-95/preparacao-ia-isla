Ambiente Python e primeiro script

Executar Python num ambiente isolado e compreender o que fica no repositório.

Pré-requisitos: Saber abrir um terminal na pasta do projeto.

Primeiro, a ideia

Python vai servir para preparar dados e treinar modelos; o navegador continua a executar HTML, CSS e JavaScript. Não precisas de abandonar a experiência de front-end. Vais acrescentar uma ferramenta para tarefas numéricas e depois comunicar resultados por ficheiros ou APIs.

Instala Python 3 a partir da fonte oficial e verifica a instalação com python --version. No Windows também podes usar py --version. Um ambiente virtual é uma pasta com um intérprete e dependências isoladas para o projeto. É semelhante a separar dependências por projeto, mas não é um equivalente exato de node_modules.

Cria o ambiente com py -m venv .venv. No Windows podes executar diretamente .venv\Scripts\python.exe, sem ativar scripts de PowerShell. Guarda código e uma lista de dependências no Git; não guardes a pasta .venv. Executar um ficheiro do início ao fim ajuda a evitar estados escondidos de notebooks.

ficheiro .py → intérprete Python → resultado no terminal

O resultado que queremos obter

No fim, vais executar um script de análise de latências, identificar o Python que o executou e compreender a saída. Primeira sessão: ambiente e ficheiros. Segunda: código, diagnóstico de erros e repetição. Usa o PowerShell no Windows; não precisas de GPU, conta de cloud ou bibliotecas de IA.

1. Editor, terminal e intérprete têm papéis diferentes

O editor guarda texto num ficheiro, como ola.py. O terminal recebe comandos para executar programas. O intérprete Python lê as instruções do ficheiro e executa-as. Abrir o ficheiro no editor não o executa, tal como abrir um ficheiro JavaScript não inicia automaticamente um processo Node.

Se escreveres apenas py no terminal, podes entrar no modo interativo de Python: aparece o prompt >>>. Aí escreves instruções Python, como print(2 + 3). Para voltar ao PowerShell, escreve exit(). Não copies os símbolos >>> para o teu ficheiro. Comandos como py ola.py pertencem ao terminal, não ao código Python.

O navegador executa o JavaScript deste site; não executa estes ficheiros Python. GitHub Pages disponibiliza o material, mas os laboratórios correm na tua máquina. Mais tarde, uma aplicação web poderá pedir previsões a um serviço Python por HTTP.

2. Confirmar antes de instalar

Abre o PowerShell e executa:

py --version
python --version

Basta um comando funcional que identifique Python 3 para prosseguires. Se ambos funcionarem, podem apontar para instalações diferentes: não assumas que são equivalentes. Nesta aula usamos py para criar o ambiente e, depois, o caminho explícito do Python desse ambiente.

Se nenhum funcionar, consulta a instalação oficial em Windows e obtém Python a partir de python.org. Reabre o terminal após a instalação e volta a verificar. A documentação atual descreve o Python Install Manager; uma instalação existente funcional não precisa de ser substituída para esta aula.

Se abrir a Microsoft Store em vez de mostrar uma versão, pode existir apenas um alias sem um intérprete disponível. Confirma a instalação segundo a documentação e verifica de novo. Não alteres variáveis do sistema ao acaso. Para este laboratório sem dependências externas, não precisas de escolher a versão mais recente só por ser mais recente.

3. Uma pasta e um ambiente por projeto

No teu editor, cria uma pasta nova chamada pratica-ia e abre um terminal nessa pasta. Se a pasta já contiver trabalho, reutiliza-a sem apagar nada. Get-Location mostra a pasta atual; Get-ChildItem lista os ficheiros. Estes são comandos PowerShell, não Python.

Get-Location
Get-ChildItem
py -m venv .venv
./.venv/Scripts/python.exe --version
./.venv/Scripts/python.exe -c "import sys; print(sys.executable)"

O argumento -m pede ao Python que execute um módulo; venv cria o ambiente e .venv é a pasta de destino. O último comando executa uma pequena instrução passada como texto com -c. sys é um módulo da biblioteca padrão e sys.executable identifica o executável usado. O caminho mostrado deve terminar em .venv/Scripts/python.exe nesta pasta.

O ambiente virtual separa as dependências Python do projeto. Não é uma máquina virtual nem um contentor completo: continua a usar o sistema operativo da tua máquina. Criá-lo não instala automaticamente NumPy ou PyTorch.

Usamos o caminho direto do executável, por isso não é necessário ativar o ambiente nem alterar a política de execução do PowerShell. Se um caminho completo tiver espaços, usa aspas e o operador de chamada &: & "C:/pasta com espaços/.venv/Scripts/python.exe" ola.py. Substitui este caminho ilustrativo pelo real.

Em macOS/Linux, o equivalente é criar com python3 -m venv .venv e executar com .venv/bin/python. O restante código da aula é igual.

4. Um script que consegues explicar

No editor, cria ola.py, guarda em UTF-8 e escreve:

latencias = [100, 110, 390]
total = sum(latencias)
quantidade = len(latencias)
media = total / quantidade
print(media)

A primeira linha atribui uma lista a latencias; os valores estão em milissegundos. sum soma os elementos: 600. len conta-os: 3. A divisão calcula 200.0, e print apresenta o resultado no terminal. Em Python, / produz uma divisão comum: 5/2 dá 2.5. O separador decimal no código é ponto, mesmo que escrevas vírgula nas contas em português.

Executa no PowerShell, na pasta do ficheiro:

./.venv/Scripts/python.exe ola.py

Deves ver 200.0. Altera 390 para 90, guarda e volta a executar: agora obténs 100.0. Se ainda vires 200.0, confirma que guardaste e que executaste o ficheiro certo. Cada execução de um script arranca um processo novo; não depende das variáveis de uma sessão interativa anterior.

A lista vazia é um caso diferente

Se latencias=[], a quantidade é zero e a divisão falha. Não inventes média zero: “não há medições” é diferente de “medimos zero”. Podes testar a lista antes da divisão e devolver None, o objeto Python que aqui significa ausência de resultado.

def calcular_media(valores):
    if not valores:
        return None
    return sum(valores) / len(valores)

print(calcular_media([]))  # None

def define a função. Os dois pontos iniciam um bloco e a indentação indica o que lhe pertence. O if executa o primeiro return quando a lista está vazia. return termina a chamada e devolve um valor. Não é igual a print: print mostra algo, mas não devolve esse resultado numérico ao chamador.

Laboratório completo

Abre ambiente.py, guarda-o na pasta de prática e executa ./.venv/Scripts/python.exe ambiente.py. O script mostra o executável, calcula média e mediana e imprime JSON. As verificações assert falham se uma expectativa não for satisfeita. O programa não cria nem altera ficheiros.

Para [100,110,390], o relatório deve mostrar quantidade 3, média 200.0 e mediana 110. Para a lista vazia, a média torna-se null no JSON, correspondente ao None em Python. A biblioteca json faz a conversão para um formato que já conheces de APIs.

5. O que instalar e o que guardar

sys, json e statistics fazem parte da biblioteca padrão usada no laboratório: não precisas de pip para os instalar. Bibliotecas externas, como NumPy, são instaladas no ambiente do projeto. Quando chegares a P02, poderás usar ./.venv/Scripts/python.exe -m pip install numpy. Não é necessário para concluir esta aula.

Usar o mesmo executável com -m pip liga a instalação ao intérprete pretendido. Para confirmar o pip, executa ./.venv/Scripts/python.exe -m pip --version. O comando ./.venv/Scripts/python.exe -m pip freeze lista dependências externas instaladas em formato utilizável para reprodução. Um ambiente sem pacotes externos pode produzir uma lista vazia; isso não significa que a biblioteca padrão esteja ausente.

Guarda no Git o código, instruções e requisitos do projeto. Exclui .venv/, que pode ser recriada e contém caminhos dependentes da máquina. Não confundas .venv com .env: este último nome é frequentemente usado para configurações e segredos, e não cria um ambiente Python. Consulta complementar: ambientes e pacotes na documentação Python.

6. Ler um erro como uma pista

Começa pela última linha da mensagem para identificar o tipo de erro; depois encontra o teu ficheiro e a linha indicados no traceback, a sequência de chamadas apresentada. Um erro numa linha pode ter origem na linha anterior, por exemplo um parêntese por fechar.

  • Ficheiro não encontrado: verifica pasta atual, nome e extensão. ola.py.txt não é ola.py.
  • SyntaxError: procura aspas, parênteses e dois pontos em falta; não copies comandos PowerShell para o código.
  • IndentationError: confirma os blocos e usa espaços de forma consistente.
  • NameError: o nome não foi definido nessa execução, ou há diferença de escrita. total e Total são nomes diferentes.
  • ModuleNotFoundError: verifica o executável e o nome do módulo antes de instalar. Não chames ao teu script json.py, pois pode esconder o módulo padrão.
  • ZeroDivisionError: verifica o denominador e o caso vazio; reinstalar Python não corrige a lógica.

Treino de diagnóstico: troca intencionalmente quantidade por Quantidade numa cópia de ola.py, executa e lê o NameError. Corrige o nome e executa novamente. O objetivo é ligar a mensagem à causa, não decorar o texto do erro.

EXEMPLO RESOLVIDO B

Um projeto isolado

Executa py -m venv .venv. Depois .venv\Scripts\python.exe -m pip --version. O caminho mostrado deve apontar para .venv. Para instalar bibliotecas nesse ambiente, usa esse mesmo intérprete com -m pip install.

Um erro a evitar

Instalar com um pip e executar com outro Python pode causar ModuleNotFoundError. Usa python -m pip com o intérprete do projeto.
